## 一、流星灯驱动与动画效果（18种）

### 1. LEDC 引脚调整
- **文件**：`apps/user_app/led_strip/led_strip_drive.h`
- `LEDC_PIN` 由 `IO_PORTB_07` 改为 `IO_PORT_DM`（USBDM，11脚）。
- 原因：PB7 被电机 `MOTOR_PIN_3` 占用；本产品无 220V 过零检测，USBDM 空闲。
- 说明：板级初始化先把 DM 设为输入，随后 `user_init → led_state_init → ledc_init` 会重新配置为 LEDC 功能输出，顺序安全。（原 `det_50hz` 过零检测模块已整体删除，见“第二轮修改”。）

### 2. 初始化顺序
- **文件**：`apps/user_app/user_main.c`
- `user_init()` 开头加入 `led_state_init()`（LEDC 引脚初始化），必须在 `full_color_init()` 之前。
- `user_main()` 主循环加入 `meteor_period_sub()`（流星周期计时，约每10ms调用一次，由 `sys_s_hi_timer`/循环节拍驱动）。

### 3. ws281x_show 填充 ledc 数据（核心）
- **文件**：`apps/user_app/ws2812-fx-lib/WS2812FX_C/ws2812_drive.c`
- 保持第0个像素 → `led_driver_set_rgbw_pwm_val()`（RGBW PWM 七彩灯）。
- 第1个像素起 → 白光流星灯带，由 `ledc_send_rgbbuf_isr()` 输出到 `LEDC_PIN`：
  - 像素格式按 `fc_effect.sequence` 自动判断 RGBW(4字节)/RGB(3字节)；
  - 取每个流星像素的 R 通道（白光亮度）连续存入全局缓冲 `buf[64]`；
  - 每3字节一组按 `rOffset/gOffset/bOffset` 重排（与参考工程一致）；
  - 按 `ceil(流星像素数/3)` 个灯位发送，附带越界防护（清零 + 长度钳制）。

### 4. 流星默认值与上电效果
- **文件**：`apps/user_app/led_strip/led_strand_effect.c`
- `fc_data_init()` 恢复流星默认值（与参考工程一致）：
  `metemor_on_off=1`、`metemor_effect_index=1`、`speed=100`、`meteor_period=8`、`period_cnt=8000`、`mode_cycle=0`。
- `full_color_init()` 恢复 `custom_meteor_effect()`（上电即跑流星效果）。
- `set_mereor_mode()` 上限由 22 改为 **18**（app 只下发18种效果）。
- 头文件 `led_strand_effect.h` 补充 `meteor_period_sub/custom_meteor_effect/set_mereor_mode` 声明。

## 三、App 下发与广播改造（FFF0/FFF1）

### 1. 广播 profile（FFF0 + FFF1）
- **文件**：`apps/spp_and_le/examples/multi_conn/ble_multi_profile.h`
- 启用 **FFF1**（WRITE|NOTIFY + CCC，句柄 0x0005/0x0006/0x0007），字节照搬参考工程（带详细中文注释）。
- **禁用** 1800/2a00 服务（`#if 0` 包裹，照参考）。
- **注释** fff2、fff3 两个特征的数据块；句柄宏只保留 `fff1` 的 0x0006/0x0007（fff2/fff3 已于第二轮彻底删除，见下文）。
- RCSP（ae01/ae02）块按原样保留在 `#if RCSP_BTMATE_EN` 中。

### 2. 从机读写回调
- **文件**：`apps/spp_and_le/examples/multi_conn/ble_multi_peripheral.c`
- **写回调**：`fff1` value → `parse_zd_data()` + `parse_led_strip_data()` + `os_taskq_post(MSG_USER_SAVE_INFO)`（原 fff2 的处理整体移入 fff1）；删除 fff2 case。
- **读回调**：删除 2a00、fff1 value（空实现）、fff3 case 及整串 `user_report_*()` 同步调用；仅保留 fff1 CCC 读。
- **连接事件**：`GATT_COMM_EVENT_CONNECTION_COMPLETE` 中新增 `user_ble_notify_connection_handle_update(temp)`。

### 3. 协议解析（dp_data_tran.c）
- **文件**：`apps/user_app/protocol/dp_data_tran.c`
- `0x0103`（与APP同步）→ 调用 `user_ble_notify_dev_all_info()` 一次性下发全部状态（替代原 `_0103_f` + fff3 读路径）。
- 各命令回读由原来的 `Send_buffer[6..]+fff3_buf_len` 死赋值，改为调用对应 notify：
  | 命令 | notify 回读 |
  |---|---|
  | 0x0101 开关灯 | `user_ble_notify_light_pwr_sta` |
  | 0x05 闹钟 | `user_ble_notify_alarm_data(idx)`（在更新 alarm_clock 之后） |
  | 0x0403 亮度 | `user_ble_notify_light_brightness` |
  | 0x0404 速度 | `user_ble_notify_light_speed` |
  | 0x0405 RGB接口 | `user_ble_notify_rgb_sequence` |
  | 0x0606 声控模式 | `user_ble_notify_sound_mode` |
  | 0x0607 声控类型 | `user_ble_notify_sound_ctl_type` |
  | 0x2F01 流星速度 | `user_ble_notify_meteor_speed` |
  | 0x2F02 流星开关 | `user_ble_notify_meteor_pwr_sta` |
  | 0x2F03 流星周期 | `user_ble_notify_meteor_period` |
  | 0x2F05 灵敏度 | `user_ble_notify_sensitive` |
  | 0x2F06 电机模式 | `user_ble_notify_motor_mode` |
  | 0x2F07 电机转速 | `user_ble_notify_motor_speed` |
- `zd_fb_2_app()` 由空函数改为真正发送：数据前加 6 字节蓝牙地址，经 `ble_comm_att_send_data()` 从 fff1 通知发出（与参考工程一致）。

### 4. user_ble_notify 模块（新增，照搬参考工程）
- **文件**（已加入 `AC632N_spp_and_le.cbp` 的 Unit 列表）：
  - `apps/user_app/protocol/user_ble_notify.h / .c`：连接句柄管理、30条指令环形缓冲、`user_ble_notify_param_handle()` 经 fff1 逐条 notify 发送；额外提供 `user_ble_notify_get_connection_handle()`。
  - `apps/user_app/protocol/user_ble_notify_app.h / .c`：16个状态 notify 函数 + `user_ble_notify_alarm_data()` + `user_ble_notify_syn_end()`；`user_ble_notify_dev_all_info()` 一次下发 19 项（参考15项 + 闹钟×3 + 同步结束）。
- **适配点**（相对参考工程）：
  - 电机字段：`fc_effect.base_ins.*`（本工程已注释）→ `motor_sec_per_round / motor_mode`，协议字节 0x2F06/0x2F07 与原 `user_report_motor_*` 映射一致；
  - 速度回显用 `fc_effect.report_speed`、灵敏度回显用内部原值；
  - dev_type 固定回 `0x02`（设备固定为 RGBW，`is_rgbw` 变量已删除）；
  - 补充闹钟3条与同步结束（0x0103）回执，保证原 app 同步流程完整。
- **任务**：
  - `app_main.c` 的 `task_info_table` 新增 `{"user_notify_task", 3, 0, 128, 128}`；
  - `user_main.c` 新增 `user_notify_task()`（循环调 `user_ble_notify_param_handle()` + `os_time_dly(1)`）并在 `user_init()` 中 `task_create`。

### 5. 保留不变
- 涂鸦协议 `parse_led_strip_data()` 保留，与中道协议共用 fff1 入口。
- （原“`user_report` 模块保留”一条已于第三轮删除，见下文。）

## 六、第二轮修改（2026-10-09）

### 1. 删除 `is_rgbw`（设备固定 RGBW，上电不再判断灯具类型）
- `led_strip_drive.c`：
  - 删除 `u8 is_rgbw` 定义；
  - `led_pwm_init()` 中删除 `gpio_read(IO_PORTB_06)` 上拉/下拉判断，固定走 RGBW（纯白灯）分支，保留 `timer_pwm_init(JL_TIMER0, IO_PORTB_06, 1000, 0)` 对 W 白光脚的 PWM 初始化；
  - `#if 0` 的 `fc_driver()` 内两处 `if (is_rgbw)` 改为固定行为。
- `led_strand_effect.c`：删除 `extern u8 is_rgbw;`；`fc_static_effect()` 删除 `if/else`，保留 RGBW 分支（彩色走 RGB、WHITE 静态效果走 `w=255`）。
- `dp_data_tran.c`：删除 `extern u8 is_rgbw;`（原 `#if 0` 块内引用随块一起删除）。
- `user_ble_notify_app.c`：`user_ble_notify_dev_type()` 固定回 `0x02`（RGBW），删除判断与 extern。

### 2. 删除 220V 50Hz 过零检测功能
- 删除模块目录 `apps/user_app/det_50hz/`（`det_50hz.c` / `det_50hz.h`，全工程无调用）。
- `.cbp`：删除 include 目录项（`../../../user_app/det_50hz`）与 `det_50hz.c` 的 Unit。
- `user_main.c`：删除 `#include "det_50hz.h"`。
- `led_strip_drive.h`：删除提到 `det_50hz` 的注释。
- `脚位和功能.md`：第 11 脚（USBDM）描述更新为「流星灯 LEDC 信号输出（原 220V 50Hz 过零检测点，本产品无此功能）」。
- `io_ext_interrupt_syn()`（DP 脚同步信号，调用本就在 `#if 0`）不属于过零检测，未改动。

### 3. fff3 / fff2 残留彻底清理（后续不再参考 fff3）
- `dp_data_tran.c`：
  - 删除 `fff3_fb_state()` 整个状态机（原 `#if 0` 块全部移除）；
  - 删除全局 `fff3_buf / fff3_buf_len / _0103_f / Send_buffer[50]` 及 `parse_zd_data` 中对它们的死操作；
  - 删除原一次性同步的整段旧注释、`fd_handle/app_send_user_data` 等死注释；
  - `0x0103` 分支的“替代原 fff3 读路径”等表述已去除。
- `ble_multi_profile.h`：删除 fff2/fff3 数据块注释与句柄宏注释，工程内不再出现 fff2/fff3。
- `user_ble_notify_app.c`：删除“与原 fff3 同步字节一致”等注释。
- 全局验证：`fff3|fff2|is_rgbw|det_50hz|_0103_f|fff3_buf` 在 `apps/`、`cpu/` 下**零残留**。

### 4. 「灯带长度」固定 16（app 下发值统一按 16 执行）
- `user_main.c` 主循环加入条件执行：
  ```c
  if (fc_effect.led_num != 16) {
      set_ls_lenght(16);
  }
  ```
  正常时 `led_num` 恒为 16、条件恒假零开销；一旦被改为其它值立即纠正（在主循环上下文执行，避免蓝牙回调中重建动画）。
- `dp_data_tran.c` 删除两处灯带长度指令处理：
  - 中道 `0x0408` 分支（原空实现与注释）；
  - 涂鸦 `case DPID_LED_NUMBER_SET` 整个分支（原写 `led_num` 处）及孤儿变量 `dp_lednum_set`。
- 保留：`set_ls_lenght()` 函数（主循环调用）、`fc_data_init()` 中 `led_num = 16` 默认值、`user_ble_notify_light_len()` 状态回读（`dev_all_info` 中仍回传 0x0408=16）。

## 七、第三轮修改（2026-10-09）

### 1. 删除 user_report 系列接口，全部适配 user_ble_notify
- **删除模块**：`apps/user_app/user_report/`（`user_report.c/h`、`user_report_app.c/h`）整体删除；`.cbp` 删除其 include 目录与 3 个 Unit。
- **任务清理**：
  - `user_main.c`：删除 `#include "user_report.h"`、`user_report_handle_task` 声明/函数体、`task_create("usr_report_task")`；
  - `app_main.c`：任务表中 `usr_report_task` 行删除（`user_notify_task` 保留）。
- **调用适配**（`rf24g_app.c` 共16处，参数本就取自 `fc_effect.*`，与 notify 版语义一致）：
  | 原 user_report 调用 | 替换为 |
  |---|---|
  | `user_report_brightness(...)` ×4 | `user_ble_notify_light_brightness()` |
  | `user_report_sound_control_sensitive(...)` ×4 | `user_ble_notify_sensitive()` |
  | `user_report_speed(...)` ×4 | `user_ble_notify_light_speed()` |
  | `user_report_sound_control_mode(...)` ×4 | `user_ble_notify_sound_mode()` |
  - `rf24g_app.c` 的 include 改为 `user_ble_notify_app.h`。
- **蓝牙侧**：
  - `ble_multi_peripheral.c`：删除 `#include "user_report_app.h"` 与 `user_conn_handle_set(temp)`（连接句柄已由 `user_ble_notify_connection_handle_update` 接管）；
  - `app_comm_ble.c`：删除 `#include "user_report.h"` 与 `user_report_self_addr_set()`（notify 不带地址前缀；`Ble_Addr` memcpy 保留供 `zd_fb_2_app` 使用）。
- **验证**：`user_report|usr_report|user_conn_handle_set` 在 `apps/` 源码与 `.cbp` 中**零残留**。

### 2. USER_DEBUG_ENABLE 使能时屏蔽 DP 脚电机驱动（DP 专用于打印）
- 背景：`board_ac632n_demo_cfg.h` 的 `TCFG_UART0_TX_PORT = IO_PORT_DP`（打印 TX 已在 DP），而 `motor_driver.h` 的 `MOTOR_PIN_1 = IO_PORT_DP`，两者冲突。
- `motor_driver.h`：新增 `#include "user_config.h"`（引入 `USER_DEBUG_ENABLE`）。
- `motor_driver.c` 用 `#if !USER_DEBUG_ENABLE` 屏蔽对 `MOTOR_PIN_1 / in1_pin`（即 DP）的 4 处写操作：
  1. `motor_set_pins()` 的步进位输出；
  2. `motor_24byj48_init()` 的 GPIO 方向/电平初始化；
  3. 步进输出函数中的 `this->in1_pin` 电平输出；
  4. `motor_24byj48_stop()` 的 `this->in1_pin` 拉低。
- 效果：`USER_DEBUG_ENABLE=1`（当前值）时 DP 仅作 UART0 打印，电机由 IN2/3/4 驱动；置 0 或未定义时电机 IN1 行为不变。
- 注：`led_gpio_init()` 中的 DP 配置本就在 `#if 0` 内，未改动。
